# 06 · Diseño UX

---

## 1. Los cuatro principios

**1 · La cajera nunca espera al sistema.**
Todo lo que se puede resolver local, se resuelve local. Ninguna acción frecuente muestra un
spinner. Si algo tarda, ocurre en segundo plano y la pantalla ya avanzó.

**2 · Una pantalla, una tarea.**
La pantalla de venta no tiene pestañas, ni menús, ni un sidebar del ERP. Tiene el buscador,
la rejilla y el carrito. Nada más. El POS entra en pantalla completa y **no comparte
navegación con el ERP** — la cajera no tiene por qué poder llegar a Producción.

**3 · Todo lo importante se ve sin desplazarse.**
Total, saldo, estado de conexión y turno están siempre visibles. Una cajera con una clienta
enfrente no hace scroll.

**4 · El error se explica y se resuelve en el mismo lugar.**
Nada de "Error 500". "Este descuento necesita aprobación de un supervisor" + el campo del PIN
justo debajo.

## 2. Sistema de diseño

Se extiende la paleta Selvedge que ya existe en `tailwind.config.ts`. **No se inventa una
paleta nueva**: se define su versión oscura.

### Color

| Token | Hex | Uso |
|---|---|---|
| `pos-bg` | `#0E1417` (ink-950) | Fondo de la aplicación |
| `pos-surface` | `#131B1F` (ink-900) | Tarjetas, carrito |
| `pos-surface-alt` | `#1A242A` (ink-800) | Filas alternas, campos |
| `pos-border` | `#243036` (ink-700) | Separadores |
| `pos-text` | `#F4F3F0` (cloud) | Texto principal |
| `pos-text-dim` | `#A6BECC` (steel-300) | Secundario |
| `pos-text-mute` | `#6F92A6` (steel-500) | Terciario, etiquetas |
| **`pos-action`** | **`#C8412B` (selvedge)** | **La acción principal. Sólo una por pantalla.** |
| `pos-ok` | `#4F6B4C` (sage) | Confirmado, stock disponible |
| `pos-warn` | `#8A6A22` (ochre) | Pendiente, stock bajo, sin conexión |
| `pos-danger` | `#B4543F` (terracotta) | Destructivo, descuadre, error |
| `pos-info` | `#37618B` (navy-500) | Informativo, sincronizando |

**Regla del rojo selvedge:** es la firma de la marca. En el POS marca **una sola cosa por
pantalla**: la acción que cierra el paso. En venta es *Cobrar*. En cobro es *Confirmar*. En
cierre es *Cerrar turno*. Si hay dos rojos en pantalla, el diseño está mal.

### Tipografía

`Futura PT` para números y títulos (ya es la fuente `display` del ERP), `Inter` para texto.

| Nivel | Tamaño / peso | Uso |
|---|---|---|
| Total | 56px / 700 tabular | El total a cobrar |
| Precio de línea | 24px / 600 tabular | Carrito |
| Título | 20px / 600 | Encabezados |
| Cuerpo | 17px / 400 | Mínimo absoluto en pantalla táctil |
| Etiqueta | 14px / 500 mayúsculas, +0.05em | Rótulos |

**Todos los números usan cifras tabulares.** Una columna de precios que baila al actualizarse
se lee mal y se cuenta peor.

### Espaciado y objetivos táctiles

| Elemento | Tamaño mínimo | Nota |
|---|---|---|
| Botón principal | 64 × 200 px | Cobrar, Confirmar |
| Tecla numérica | 72 × 72 px | Se usa a ciegas |
| Fila del carrito | 72 px de alto | Con +/− tocables |
| Tarjeta de producto | 160 × 200 px | Foto + talla + stock |
| Separación mínima | 12 px | Entre objetivos táctiles |
| Zona de pulgar | Inferior derecha | Ahí van las acciones frecuentes |

Rejilla base de 8px. Radio 8px (`md` del tema actual), 12px en tarjetas.

### Movimiento

| Interacción | Duración | Curva |
|---|---|---|
| Línea agregada al carrito | 120 ms | `ease-out` — entra desde arriba |
| Panel de cobro | 240 ms | `cubic-bezier(.32,.72,0,1)` (ya en el tema) |
| Cambio de total | 0 ms | **Instantáneo.** Un número que anima es un número que no se puede leer. |
| Diálogo | 180 ms | Escala 0.96 → 1 |

Se respeta `prefers-reduced-motion`.

### Retroalimentación no visual

La cajera **no mira la pantalla** mientras escanea. Mira la prenda.

| Evento | Sonido | Vibración |
|---|---|---|
| Escaneo correcto | *clic* corto, 40 ms | 10 ms |
| Producto no encontrado | *bip* grave doble | 2 × 30 ms |
| Venta cerrada | *ding* ascendente | 50 ms |
| Error | *bip* grave largo | 200 ms |

Todo silenciable, pero **activo por defecto**: es lo que permite escanear sin mirar.

**Decisiones de esta pantalla:**

- **El buscador siempre tiene el foco.** El lector de códigos es un teclado: escribe ahí sin
  que nadie haga clic. Coincidencia exacta de código de barras ⇒ la línea se agrega sola y el
  campo se limpia. Cero clics por prenda.
- **Rejilla con foto**, no una lista. En moda, la cajera reconoce la prenda por la imagen más
  rápido que por el nombre.
- **La talla es parte de la tarjeta**, no un segundo paso. Buscar `93634` muestra todas las
  tallas de esa referencia como tarjetas distintas: se toca la correcta y listo.
- **El total ocupa 56px.** Es el número que la clienta pregunta.
- **El carrito ocupa un tercio fijo.** No colapsa, no se esconde, no requiere scroll con menos
  de 8 líneas.

## 4. Atajos de teclado

El POS se maneja con mouse o con dedos, pero una cajera experta va el doble de rápido con
teclado. Los atajos se muestran en la interfaz, no se esconden.

| Tecla | Acción |
|---|---|
| Cualquier carácter | Escribe en el buscador (siempre enfocado) |
| `Enter` | Agrega el primer resultado / confirma |
| `F1` | Ayuda |
| `F2` | Buscar producto |
| `F3` | Buscar cliente |
| **`F4`** | **Cobrar** |
| `F8` | Descuento |
| `F9` | Quitar línea |
| `F12` | Confirmar cobro |
| `Esc` | Cancelar / volver |
| `+` / `−` | Cantidad de la línea seleccionada |
| `↑` `↓` | Navegar el carrito |
| `Ctrl+P` | Reimprimir |
| `Ctrl+K` | Paleta de comandos (ya existe en el ERP) |

## 5. Accesibilidad y realidad de tienda

| Situación real | Decisión de diseño |
|---|---|
| Iluminación fuerte de vitrina sobre pantalla oscura | Contraste mínimo 7:1 en texto principal (AAA), no 4,5:1 |
| Cajera con uñas largas o guantes | Objetivos táctiles ≥ 64px, separación ≥ 12px |
| Pantalla táctil con grasa y huellas | Nada crítico depende de gestos finos ni de arrastrar |
| Ruido del centro comercial | Retroalimentación **visual y sonora y háptica**, no sólo una |
| Turnos de 10 horas | Tema oscuro por defecto; sin blancos puros (`#F4F3F0`, no `#FFF`) |
| Cajera nueva en su primer día | Los atajos visibles en pantalla; el camino principal se recorre sin aprender nada |
| Clienta mirando la pantalla | Ningún dato de otra clienta visible en la pantalla de venta |

---

## 6. Lo que este POS **no** hace, a propósito

| No hace | Por qué |
|---|---|
| No tiene menú lateral en la pantalla de venta | Cada elemento de navegación es una forma de salirse de la tarea |
| No pide confirmación al agregar una prenda | Quitar es un toque; confirmar cada adición son 47 toques por turno |
| No muestra márgenes ni costos | La cajera no negocia precio. Ese dato es de gerencia. |
| No permite editar el precio a mano | Sólo descuentos, con tope y con firma. Editar el precio es el agujero clásico. |
| No abre modales por pérdida de conexión | Detendría una venta que podía continuar |
| No anima el total | Un número que se mueve no se puede leer |
